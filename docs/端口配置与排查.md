# 项目端口配置与排查

本文说明如何确定项目实际监听的端口，以及如何让 Docker 和 Zeabur 的端口设置与之匹配。

## 先区分三个端口

1. **应用监听端口**：应用进程实际绑定的容器端口。这是最重要的值。
2. **Docker `EXPOSE` 端口**：镜像元数据中的端口提示，不会自动让应用监听该端口，也不会自动发布端口。
3. **平台目标端口**：Zeabur 网络设置把流量转发到的容器端口。它必须与应用监听端口相同。

例如，应用监听 `8080`，Docker 写着 `EXPOSE 3000`，Zeabur 却转发到 `3000`，外部访问通常会失败。应让应用监听端口和 Zeabur 目标端口都为 `8080`；`EXPOSE` 可随后改为 `8080` 以保持说明一致。

## 如何在项目中查端口

### 1. 查启动命令

检查 `package.json` 的 `scripts`、Dockerfile 的 `CMD` / `ENTRYPOINT`，以及进程管理器或启动脚本。留意这些形式：

```text
next start --port 3000
next start -p 3000
node server.js
```

显式传给启动命令的端口通常优先于框架默认值。若启动 `server.js`，继续查该文件如何读取 `PORT`。

### 2. 查环境变量

在代码和配置中搜索 `PORT`、`process.env.PORT`、`listen(`、`--port`：

```powershell
rg -n "PORT|listen\(|--port|-p 3000" --glob "!yarn.lock" --glob "!package-lock.json" .
```

常见写法是读取 `process.env.PORT`，没有设置时使用一个默认值。部署平台上的 `PORT` 可能覆盖本地默认值。

### 3. 查容器和编排配置

- Dockerfile：查 `EXPOSE`，把它当作文档提示，不要单独据此判断应用实际监听值。
- Docker Compose：检查 `ports`。格式通常是 `主机端口:容器端口`，右侧容器端口必须对应应用监听端口。
- Zeabur：查看服务“网络”中的 HTTP 端口，它是平台转发的目标端口；同时查看服务环境变量中 `PORT` 的**实际解析值**。

### 4. 查运行日志

部署启动后查看运行日志。Next.js 常会打印类似 `Ready on ...:3000` 或 `Listening on ...:8080` 的信息。将日志中的监听端口与 Zeabur 网络目标端口对照。构建日志里的 `PORT` secret mount 只说明构建步骤可取得变量，不能单独证明运行时监听端口正确。

## 本项目 NotionNext 的端口

当前仓库的 Dockerfile：

- 使用 `node:22-alpine`；
- 运行命令为 `CMD ["node", "server.js"]`；
- 声明了 `EXPOSE 3000`。

Next.js standalone 服务器默认端口为 `3000`，并会读取运行时的 `PORT` 环境变量。因此：

- 若 Zeabur 运行时 `PORT` 实际值是 `8080`，网络设置中的 HTTP 目标端口应为 `8080`；
- 若没有 `PORT` 覆盖，应用默认监听 `3000`，Zeabur HTTP 目标端口应设为 `3000`。

目前 Zeabur 环境变量界面显示 `PORT=${WEB_PORT}`，网络界面显示 HTTP `8080`。请确认该引用在运行时解析为 `8080`。为减少变量引用歧义，也可以在该服务把 `PORT` 设为字面值 `8080`，并保持 Zeabur 网络 HTTP 端口为 `8080`，然后重新部署。

## 排错顺序

1. 先从运行日志确定进程实际监听的端口。
2. 检查 Zeabur 网络设置中的 HTTP 目标端口是否相同。
3. 检查 `PORT` 环境变量是否在运行时生效，以及 `${WEB_PORT}` 是否被解析成数字。
4. 如果项目启动命令写死了端口，改启动命令或改平台目标端口，使二者一致。
5. Docker `EXPOSE` 可同步成同一个数字，方便维护，但它本身不会改变应用监听端口。
